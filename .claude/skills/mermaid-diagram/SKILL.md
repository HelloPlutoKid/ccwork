# mermaid-diagram

`src/` 디렉토리를 분석해 두 개의 Mermaid 다이어그램(컴포넌트 import 의존성 + 상태/데이터 흐름)을 단일 HTML(`docs/architecture/index.html`)로 출력하고, OS 의 기본 브라우저로 자동으로 띄운다.

## 발동 조건

- 사용자가 `/mermaid-diagram` 으로 직접 호출
- 또는 PostToolUse hook 의 reminder("src/ 변경 감지 …")를 본 직후

## 절차

### 1. src/ 분석

`src/**/*.{ts,tsx}` 의 파일을 모두 읽고 각 파일의 **정적 import** 문을 추출한다. 노드/엣지 규칙:

- **노드**: 모듈 단위(파일 1개 = 노드 1개). 같은 파일의 named export 들(예: `NotesProvider` + `useNotes`)은 한 노드 안 라벨로 표기.
- **엣지**: A 가 B 를 import 하면 `A --> B`. 외부 패키지(react 등)는 생략.
- 라벨에는 상대 경로(`components/NoteList.tsx`)와 주요 export 이름을 포함.

### 2. 상태/데이터 흐름 정의

정적 분석으로는 못 잡는 런타임 흐름을 LLM 가 직접 그린다. 표현 대상:

- 영속 계층: `db.json` ↔ `json-server :3001`
- HTTP: `json-server` ↔ `src/api/notes.ts`
- 스토어: `api/notes.ts` ↔ `NotesContext`
- 뷰: `NotesContext` ↔ `NoteList`/`NoteEditor`/`NoteItem`
- 컨트롤(콜백): 자식 → 부모 `on*` props, 컴포넌트 → Context 메서드

### 3. HTML 작성

아래 템플릿을 사용해 `docs/architecture/index.html` 을 **UTF-8**로 Write 한다. `<MERMAID_COMPONENT_GRAPH>` 와 `<MERMAID_STATE_FLOW>` 자리에 실제 mermaid 코드를 채워 넣는다.

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8" />
  <title>ccwork · Architecture</title>
  <style>
    body { font-family: system-ui, sans-serif; max-width: 1100px; margin: 2rem auto; padding: 0 1rem; }
    h1, h2 { margin-top: 2rem; }
    .mermaid { background: #fff; padding: 1rem; border: 1px solid #e5e5e5; border-radius: 8px; }
    @media (prefers-color-scheme: dark) {
      body { background:#111; color:#eee; }
      .mermaid { background:#1b1b1b; border-color:#333; }
    }
    .note { color:#888; font-size: 0.85rem; }
  </style>
</head>
<body>
  <h1>ccwork — Architecture</h1>
  <p class="note">Generated by the <code>mermaid-diagram</code> skill. 갱신: <code>/mermaid-diagram</code></p>

  <h2>Component dependency graph (import 관계)</h2>
  <pre class="mermaid">
<MERMAID_COMPONENT_GRAPH>
  </pre>

  <h2>State / data flow</h2>
  <pre class="mermaid">
<MERMAID_STATE_FLOW>
  </pre>

  <script type="module">
    import mermaid from 'https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs';
    mermaid.initialize({
      startOnLoad: true,
      theme: matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'default'
    });
  </script>
</body>
</html>
```

### 4. 브라우저 자동 열기

OS 를 감지해 한 번만 실행 (인자에 `--no-open` 이 있으면 생략):

| OS | 명령 |
|----|------|
| Windows | `powershell -NoProfile -Command "Start-Process docs\architecture\index.html"` |
| macOS | `open docs/architecture/index.html` |
| Linux | `xdg-open docs/architecture/index.html` |

이미 같은 페이지를 열어둔 사용자에게는 새 탭이 열린다는 점만 안내.

### 5. 종료 보고

한두 줄로:
- `docs/architecture/index.html 생성 완료`
- `nodes: N, edges: M (component graph)` + `nodes: N, edges: M (state flow)`
- `갱신: /mermaid-diagram (또는 "mermaid-diagram skill 실행")`

## 참고 (현재 스냅샷)

작성 시점의 컴포넌트 그래프(예시 — 매 실행마다 다시 그린다):

```
graph TD
  main[main.tsx] --> App[App.tsx]
  App --> NotesCtx["context/NotesContext.tsx<br/>(NotesProvider · useNotes)"]
  App --> Layout[components/Layout.tsx]
  App --> NoteList[components/NoteList.tsx]
  App --> NoteEditor[components/NoteEditor.tsx]
  NoteList --> NotesCtx
  NoteList --> NoteItem[components/NoteItem.tsx]
  NoteEditor --> NotesCtx
  NotesCtx --> Api[api/notes.ts]
  NotesCtx --> Types[types/note.ts]
  Api --> Types
  NoteItem --> Types
```

## 주의

- CDN(`cdn.jsdelivr.net`) 차단 환경이면 페이지가 빈 화면이 된다 — 그 경우 `npm i -D mermaid` 후 `node_modules/mermaid/dist/mermaid.esm.min.mjs` 로 import 경로를 바꾸는 후속 보강.
- 매 발동은 새 탭/창을 연다. 자동 reload 는 지원 안 함.
- 출력 파일은 `docs/architecture/` 한 곳에만. 다른 경로로 분산하지 말 것.
